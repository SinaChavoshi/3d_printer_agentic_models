An AI-powered parametric 3D CAD studio: describe a part in plain language and an LLM writes Python (`trimesh` + `manifold3d`) code that builds it. The code runs in a sandbox, the result is shown in an interactive WebGL viewer, and you can download a watertight binary `.stl` for 3D printing.

The repository also hosts a library of OpenSCAD models (with thumbnails and one-click OpenSCAD Playground links) and fishing-lure simulation tools.

---

## ⚡ OpenSCAD Studio: the same experience with no server

[`studio/index.html`](studio/index.html) is a single static page with a chat-based CAD studio. You describe a part, Claude (or Gemini) writes **OpenSCAD**, your browser renders it, and you download a watertight STL. Nothing needs to be installed or hosted.

**[▶ Launch OpenSCAD Studio](https://sinachavoshi.github.io/3d_printer_agentic_models/studio/)**: opens the page in your browser. Clicking `studio/index.html` only shows its source. Or run it locally: `python3 -m http.server -d studio 8000`, then open <http://localhost:8000>

* **Chat thread.** Each reply becomes a numbered version. Keep asking for changes ("add two screw holes", "make it 20 mm taller"). You can restore any earlier version or view its code.
* **Runs entirely in the browser.** The page calls the Claude or Gemini API directly with **your own API key**. The key is stored only in your browser and sent only to that provider. OpenSCAD 2025 (WebAssembly build, Manifold backend) renders in a Web Worker. Three.js shows the result, and the binary STL is built in memory.
* **Same agent loop as the server.** Generate → render → if OpenSCAD fails, the error goes back to the model to fix (up to 2 retries) → optional **visual check**, where the model looks at isometric, top and front renders and corrects the design.
* **Your code, your files.** The source is editable in the `</> Code` panel and can be re-rendered by hand. Download both the `.stl` and the `.scad`, so a design can go straight into the gallery below.
* **📚 Library.** Open any model from [`generated_models/openscad`](generated_models/openscad) and iterate on it in chat.
* `text()` works (the DejaVu Sans font is loaded; other font names fall back to it). External libraries such as BOSL2 and MCAD are not available.

> [!NOTE]
> Because there is no server, every user supplies their own key. Don't host this page with a key built in. The page's Content-Security-Policy only allows connections to the two LLM APIs, the jsDelivr CDN and GitHub, and it checks the OpenSCAD download against a pinned SHA-384 hash before running it.

## 🌊 Lure Simulation Tools

One of the hobbies behind this project is designing trolling lures, so the repo includes two ways to see how a lure behaves when it is dragged through water.

### 1. LureHydro 3D (browser, real-time)

Load any lure STL (OpenSCAD exports work as-is, ASCII or binary, in mm) and watch it trolled on a leader. **The motion is computed from the lure's actual geometry, not scripted:**
- Water forces are integrated over about 3,000 surface patches at 1,000 Hz: pressure, suction, skin friction, added mass and vortex shedding.
- Mass and buoyancy come from your print settings: material, infill, wall thickness, ballast and hooks.
- It supports eye-tied or line-through rigging, and limited fluctuations: turbulence, boat surge and heave, and flasher sway.
- Telemetry shows roll rpm, wobble frequency and amplitude, sway, line angle, drag and net buoyancy.

It's a reduced-order model, good for comparing designs, tow points and ballast. It is not CFD.

[👉 Launch LureHydro 3D](https://htmlpreview.github.io/?https://raw.githubusercontent.com/SinaChavoshi/3d_printer_agentic_models/refs/heads/main/tools/simulators/lure_hydrodynamics_simulator/index.html) · [Model details & limitations](tools/simulators/lure_hydrodynamics_simulator/README.md) · headless check: `node tools/simulators/lure_hydrodynamics_simulator/physics_check.mjs --quick`

![Simulator Screenshot](tools/simulators/lure_hydrodynamics_simulator/screenshot.png)

### 2. OpenFOAM pipeline (high-fidelity CFD)

For the designs that look promising, [`tools/cfd/openfoam_lure/`](tools/cfd/openfoam_lure/README.md) turns a lure STL into a ready-to-run **OpenFOAM v2412** case:
- The lure is free in all 6 degrees of freedom on an overset mesh, towed on a leader, with URANS k-ω SST turbulence.
- `postprocess.py` reports roll rpm, wobble frequency (FFT), sway, line angle and drag, with plots and a ParaView animation.

> [!NOTE]
> The pipeline was written against the OpenFOAM v2412 tutorials and sources, and its Python tools are tested. OpenFOAM itself hasn't been run on it yet, so expect small fixes on the first run (see its README).

## 🌟 Key Features

* **AI-Driven Parametric CAD:** An LLM (Gemini by default; Claude, GPT, Grok, DeepSeek, Kimi, or a self-hosted model) writes Python `trimesh` code for your part.
* **Sandboxed Execution:** Generated code runs in a separate, resource-limited process with a timeout, and can only use `trimesh`, `numpy`, and `math` (no file, network, or OS access).
* **Auto-Correction Loop:** If the code fails, the error, the failing code, and your request are sent back to the model to fix it (up to 2 retries). Failures are reported, never silently replaced.
* **Visual Refinement (Gemini):** The model inspects rendered snapshots of its own result and revises the code if it doesn't match the request.
* **Watertight CSG Booleans:** `manifold3d` engine for reliable unions, differences, and intersections.
* **Interactive 3D Viewer & Print Analyzer:** Three.js viewer with bounding box (mm), volume (mm³), face count, and watertight status; one-click binary `.stl` download.
* **OpenSCAD Model Library:** Hand-designed models with thumbnails and OpenSCAD Playground links (see the gallery above).

## 🚀 Getting Started

> These steps run the original Python server (trimesh-based, many providers). For the no-install version, use [OpenSCAD Studio](#-openscad-studio-the-same-experience-with-no-server) above.

### Prerequisites
* Python 3.11 or higher
* [`uv`](https://docs.astral.sh/uv/) package manager (recommended) or `pip`
* Credentials for at least one LLM provider (see Configuration)

### 1. Installation

```bash
git clone https://github.com/SinaChavoshi/3d_printer_agentic_models.git
cd 3d_printer_agentic_models
uv sync
```

### 2. Running the Server Locally

```bash
uv run uvicorn app.server:app --host 127.0.0.1 --port 8088
```

Open **`http://localhost:8088`**. The server only listens on localhost by default; see the note below before exposing it.

### 3. Configuration

Copy `.env.example` to `.env` (or export the variables) and set what you need:

| Variable | Purpose |
| :--- | :--- |
| `GEMINI_API_KEY` *or* ADC + `GOOGLE_CLOUD_PROJECT` / `GOOGLE_CLOUD_LOCATION` | Google Gemini (API key or Vertex AI) |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `XAI_API_KEY`, `DEEPSEEK_API_KEY`, `MOONSHOT_API_KEY` | Keys for other providers. Each key is only ever sent to its own provider. |
| `LLM_BASE_URL`, `LLM_API_KEY` | Endpoint (and optional key) for a self-hosted OpenAI-compatible server (default `http://localhost:11434/v1`). |
| `LLM_ALLOWED_BASE_URLS` | Comma-separated endpoints that users may pick in the UI's "Custom Base URL". Anything else is rejected. |
| `STUDIO_ACCESS_TOKEN` | If set, every API call must send it in the `X-Studio-Token` header (enter it in the UI settings). |
| `CORS_ALLOW_ORIGINS` | Extra origins allowed to call the API from a browser (off by default; the UI is same-origin). |
| `CAD_EXEC_TIMEOUT_SECONDS`, `CAD_EXEC_MEMORY_MB` | Sandbox limits for generated code (defaults: 60 s, 4096 MB). |

> [!WARNING]
> Users of the studio can make it call your LLM keys. If you bind to anything other than `127.0.0.1` or deploy the container, set `STUDIO_ACCESS_TOKEN`.

### 4. Docker

```bash
docker build -t cad-studio .
docker run --rm -p 127.0.0.1:8080:8080 --env-file .env cad-studio
```

## 🧩 Adding an OpenSCAD Model

```bash
# 1. Extract the active file from your OpenSCAD Playground share link
#    (prints a warning if the customizer overrides any defaults; add --apply-vars to keep them)
python tools/decode_scad.py "<playground-url>" generated_models/openscad/<name>/<name>.scad

# 2. Render the thumbnail (needs openscad + xvfb) and export the print-ready STL
./tools/render_scad/render.sh generated_models/openscad/<name>/<name>.scad
python tools/render_scad/export_stl.py generated_models/openscad/<name>
#    (multi-part models: add their per-part settings to PARTS in export_stl.py)

# 3. After editing a .scad, regenerate its README link so it matches the code
python tools/encode_scad.py generated_models/openscad/<name>/<name>.scad --template-url "<old-url>"
```

Then add a `README.md` next to the model (with a Download section) and a row to both gallery tables.
